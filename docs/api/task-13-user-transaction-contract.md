# TASK-13 user transaction contract

- `GET /api/v1/flash-sale-activities` is explicitly anonymous and returns current/upcoming activity facts with `serverTime` for calibrated countdowns.
- `POST /api/v1/orders` requires `Idempotency-Key`. A new intent returns 201; an exact durable replay returns 200 plus the reusable boolean response header `Idempotency-Replayed: true`; reusing the key with a different request fingerprint returns 409. Both success responses use `application/json` with `OrderCreatedResponse`, preserve the original `requestId`, and expose whether the result is an idempotent replay. The 409 response explicitly uses `application/problem+json` with `ApiProblem`; it is not an undocumented empty/error response. The raw key is never persisted.
- `GET /api/v1/orders/{orderId}` and `GET /api/v1/orders/{orderId}/timeline` expose only the authenticated User's resource. Unknown and other-User identifiers both use 404.
- Authenticated SSE endpoints are `GET /api/v1/orders/{orderId}/events` and `GET /api/v1/flash-sales/{activityId}/reservations/{reservationNo}/events`. Resume cursors use the `Last-Event-ID` header; bearer tokens are never URL parameters.
- SSE event IDs are monotonic MySQL `user_transaction_timeline.event_id` values. The durable timeline is the recovery source. The browser accepts only a canonical non-negative decimal ID whose `BigInt` value is strictly greater than the latest accepted ID; an equal/older event or an illegal state transition changes neither the latest state nor the visible event list. `LATE_SUCCEEDED` is accepted only after `CLOSED` or `CANCELED`, never after `PAID` or `COMPENSATED`. Order detail, timeline GET, and SSE are read-only and never reconcile or append events.
- Each timeline row is the first authoritative receipt of one resource/event fact, not an unlimited audit record of retries or repeated assignments.
- Event names include `RESERVED`, `ORDER_CREATED`, `PENDING_PAYMENT`, `PAYMENT_FAILED`, `PAID`, `CLOSED`, `CANCELED`, `COMPENSATING`, `COMPENSATED`, and `LATE_SUCCEEDED` when those facts exist.
- An SSE connection polls committed timeline rows every 2 seconds, sends a heartbeat every 15 seconds, and expires after 30 minutes. A Portal instance uses an explicit eight-thread `ScheduledThreadPoolExecutor`, enables remove-on-cancel, and accepts at most 200 concurrent streams. Completion, timeout, error, client abort, and shutdown remove the scheduled task and release the connection permit. Emitter-factory or scheduler failure during initialization leaves no registered emitter, queued task, or leaked active-connection count.
- Activity responses require stable identity, lifecycle, stock, price, and server-time fields. Order creation responses require `requestId` and `idempotencyReplayed`; timeline responses require the durable event identity, resource identity, event type, occurrence time, and request/trace fields defined by the schema.
- Activity controls expose distinct `SOLD_OUT` and `EXPIRED` states. The former renders "已售罄" and the latter "已过期" with different disabled explanations. Stream live, reconnecting, and offline transitions are available to assistive technology.
- Each browser stream attempt has an increasing generation. Callbacks may dispatch only while their generation is current, the attempt is active, and its abort signal is not aborted. The parser accepts CR, LF, and CRLF framing across arbitrary network chunk boundaries and flushes decoder/tail data at EOF.
- V1.7 accepts only lowercase 64-character hexadecimal SHA-256 hashes/fingerprints. `traceparent` is checked case-sensitively, excludes version `ff`, all-zero trace IDs, and all-zero parent IDs. The migration defines no foreign keys.
- `occurredAt` is mandatory when a timeline receipt is written; a missing authoritative timestamp fails rather than being replaced by the current time.
- `tracestate` crosses ordinary-order creation, Flash Sale order/timeout Outbox payloads, payment callback processing, payment-result Outbox payloads, and the final broker message header. Tracing/metrics/span creation is non-authoritative: failure cannot prevent Stream consumption or Outbox publication, and worker MDC/trace context is restored after each attempt.

The checked-in public, user, and admin OpenAPI baselines are runtime exports. The reusable `IdempotencyReplayed` response-header component has a boolean schema, and the generated clients in `web/src/api/generated` must remain drift-free.
